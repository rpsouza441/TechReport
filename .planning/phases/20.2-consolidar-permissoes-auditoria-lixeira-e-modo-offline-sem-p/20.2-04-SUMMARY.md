# Phase 20.2 Plan 04: Exclusive Active Identity Guard Summary

**Transactional migration 0025 prevents any Auth user from being active simultaneously as an app admin and company member across direct writes, invitations, acceptance and reactivation.**

## Accomplishments

- Added a non-destructive precondition that aborts with SQLSTATE `P2003` when an existing active dual identity is found.
- Added bidirectional `BEFORE INSERT OR UPDATE` trigger guards for `app_admins` and `tecnicos`, including concurrency serialization for the same Auth user.
- Recreated the four effective invite/team RPCs with their original signatures, validation, idempotency and role semantics plus early active-app-admin checks.
- Revoked PUBLIC/anonymous execution, kept trigger helpers inaccessible to client roles and granted only the required RPCs to `authenticated`.

## Files Created/Modified

## Decisions Made

- Used the same advisory transaction-lock key on both activation paths; table checks alone would allow two concurrent first activations to observe neither counterpart.
- Reused SQLSTATE `P2003` for the migration precondition, direct-write triggers and RPC guards so identity conflicts are distinguishable without deleting or selecting a winning profile.
- Preserved inactive historical profiles and migration 0023 unchanged; only transitions that would produce two active privilege domains are rejected.

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Serialized concurrent cross-table activations**

- **Found during:** Task 1 (Implement bidirectional identity exclusion and guarded RPCs)
- **Issue:** Independent existence checks in two table triggers could both pass during simultaneous first inserts for the same Auth user.
- **Fix:** Both trigger functions acquire the same transaction-scoped advisory lock derived from `user_id` before checking the opposite table.
- **Files modified:** `supabase/migrations/0025_guard_app_admin_company_identity.sql`
- **Verification:** Static inspection confirms two matching `pg_advisory_xact_lock` calls before the opposite-table checks.
